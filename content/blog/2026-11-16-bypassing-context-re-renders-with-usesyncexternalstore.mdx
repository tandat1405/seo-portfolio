React Context is frequently misused as a state management solution. While it excels at dependency injection and passing down ambient data like active themes or auth credentials, using standard Context to pass mutable, high-frequency state creates severe performance bottlenecks. Because React’s Context propagation relies on total value identity, any update to a property inside a Context object forces every consuming component down the Fiber tree to re-render—completely bypassing `React.memo` boundaries.

To eliminate these re-render cascades without pulling in heavy external state management libraries, we can pair Context with React 18’s native `useSyncExternalStore` hook. This approach allows us to use Context purely for dependency injection while delegating state updates and fine-grained subscriptions to a lightweight external store.

## The Flaw in Context Propagation

When a React Context provider's value changes, React marks all descendant Fiber nodes that consume that context via `useContext` as needing work. 

```tsx
// ❌ Traditional Context pattern: Every consumer re-renders on ANY state change
const DashboardContext = createContext<DashboardState | null>(null);

export const DashboardProvider = ({ children }: { children: ReactNode }) => {
  const [state, setState] = useState<DashboardState>({ user: {...}, metrics: {...} });

  // Whenever metrics update, components reading ONLY `state.user` still re-render!
  return (
    <DashboardContext.Provider value={state}>
      {children}
    </DashboardContext.Provider>
  );
};
```

Because `useContext` returns the entire context object, React cannot natively infer which specific properties a component actually depends on. Component-level memoization (`React.memo`, `useMemo`) fails here because the Context consumer's internal call to `useContext` triggers a re-render *before* any prop-level checks can execute.

In React Native environments—where JavaScript thread time directly impacts gesture responsiveness and frame delivery—these unnecessary re-render cascades lead to visible drop frames during rapid updates like scroll events, form inputs, or WebSocket streams.

## Decoupling Render from the Fiber Tree

To fix this, we must separate **state storage** from **React's component tree**. By moving state into an external pub/sub container and passing *only the stable store instance* through Context, the Context value reference never changes. 

`useSyncExternalStore` acts as the bridge. It subscribes directly to the external store and triggers a component re-render **only** when the specific slice of state selected by `getSnapshot` changes according to `Object.is`.

```
[ Context Provider ] ---> Passes stable Store reference (0 re-renders)
                                  |
            +---------------------+---------------------+
            |                                           |
    [ Component A ]                             [ Component B ]
    useSyncExternalStore(selectorA)            useSyncExternalStore(selectorB)
            |                                           |
    Subscribes to Store                         Subscribes to Store
    Re-renders ONLY when A changes              Re-renders ONLY when B changes
```

## Implementing a Vanilla Selector-Based Store

Let's implement a minimal, type-safe, external store without external dependencies.

### 1. The Core Store Implementation

```typescript
type Listener = () => void;

export class Store<T extends object> {
  private state: T;
  private listeners = new Set<Listener>();

  constructor(initialState: T) {
    this.state = initialState;
  }

  // Stable getter method
  get = (): T => this.state;

  // Mutate state and notify subscribers
  set = (partial: Partial<T> | ((prev: T) => T)): void => {
    const nextState =
      typeof partial === 'function' ? partial(this.state) : partial;

    if (!Object.is(this.state, nextState)) {
      this.state = typeof partial === 'function' 
        ? nextState 
        : { ...this.state, ...partial };
      
      // Batch notification to listeners
      this.listeners.forEach((listener) => listener());
    }
  };

  // Subscribe pattern expected by useSyncExternalStore
  subscribe = (listener: Listener): (() => void) => {
    this.listeners.add(listener);
    return () => this.listeners.delete(listener);
  };
}
```

### 2. Context Binding and Custom Selector Hook

Next, we expose the store via Context and build a selector hook utilizing `useSyncExternalStore`.

```tsx
import React, { createContext, useContext, useRef, useSyncExternalStore, useCallback } from 'react';

const StoreContext = createContext<Store<any> | null>(null);

export const StoreProvider = <T extends object>({ 
  initialState, 
  children 
}: { 
  initialState: T; 
  children: React.ReactNode; 
}) => {
  // Use a ref to guarantee the Store instance identity never changes
  const storeRef = useRef<Store<T> | null>(null);
  if (!storeRef.current) {
    storeRef.current = new Store<T>(initialState);
  }

  return (
    <StoreContext.Provider value={storeRef.current}>
      {children}
    </StoreContext.Provider>
  );
};

export function useStoreSelector<T extends object, R>(
  selector: (state: T) => R
): R {
  const store = useContext(StoreContext);
  if (!store) {
    throw new Error('useStoreSelector must be used within a StoreProvider');
  }

  // Wrap getSnapshot to execute selector against store state
  const getSnapshot = useCallback(
    () => selector(store.get()),
    [store, selector]
  );

  return useSyncExternalStore(
    store.subscribe,
    getSnapshot,
    getSnapshot // Fallback for SSR
  );
}
```

## Consuming Fine-Grained State

Now, components subscribe to isolated slices of the state tree.

```tsx
// Component A only re-renders when `user.name` changes
const UserProfile = () => {
  const userName = useStoreSelector(
    useCallback((state: DashboardState) => state.user.name, [])
  );

  return <Text>{userName}</Text>;
};

// Component B only re-renders when `metrics.fps` changes
const PerformanceBadge = () => {
  const fps = useStoreSelector(
    useCallback((state: DashboardState) => state.metrics.fps, [])
  );

  return <Text>FPS: {fps}</Text>;
};
```

When `metrics.fps` updates in the store, `UserProfile` does not execute a render phase. The Fiber nodes corresponding to `UserProfile` are skipped entirely during reconciliation.

## Crucial Pitfalls: Referential Stability and Tearing

Senior engineers must keep two key mechanics in mind when using `useSyncExternalStore`:

### 1. Avoiding `getSnapshot` Infinite Loops
`useSyncExternalStore` uses strict equality (`Object.is`) to compare the result of `getSnapshot()` between updates. If your selector returns a new object literal every invocation, React will throw an infinite re-render error.

```typescript
// ❌ DANGER: Returns a new object reference on every invocation
const { firstname, lastname } = useStoreSelector(
  (state) => ({ firstname: state.user.first, lastname: state.user.last })
);

// ✅ SAFE: Returns primitive values or memoized object structures
const firstname = useStoreSelector((state) => state.user.first);
const lastname = useStoreSelector((state) => state.user.last);
```

If you must derive object snapshots, integrate a custom comparison engine or shallow equality check inside a custom hook abstraction like `useSyncExternalStoreWithSelector` from the `use-sync-external-store/shim/with-selector` package.

### 2. Preventing Concurrent Tearing
Before React 18, subscribing to external stores inside `useEffect` led to "tearing"—a visual inconsistency where different components render data from different versions of the store during a single concurrent transition. `useSyncExternalStore` solves this by forcing synchronous evaluation of the store snapshot during rendering transitions, guaranteeing state consistency across the entire tree.

## Conclusion

Bypassing Context re-render cascades does not require adopting massive state-management ecosystems when native primitives suffice. By shifting state out of the Fiber tree and using React Context purely for dependency injection:

1. **Context Providers** maintain a stable store reference, insulating child components from re-renders.
2. **`useSyncExternalStore`** handles subscription logic, opting components into updates strictly when selected primitives mutate.
3. **Execution paths** become deterministic, reducing thread work in both web and React Native applications.
